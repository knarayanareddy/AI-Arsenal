# AI-Arsenal review

## Scope and verdict

Pinned SHA `8ec0eef7698bccd93bddf089d0b49de67c858a93`. This is an implemented schema-driven content collection with automation and a separate `web/` frontend. Runtime, builds, tests and deployment: **NOT RUN**. README contains conflicting catalog totals and describes the UI as future despite a web package and Pages deployment workflow in the same revision. Historical refresh failures and publication integrity need investigation before treating the generated data as current.

Reviewed snapshot samples include `README.md:1-300` of a larger document, root and web package manifests, and the sampled workflows `codeql`, `data-refresh`, `deploy-pages`, `manual`, `monthly`, `no-skip-ci`, `on-merge`, `on-pr` and `release`. The non-truncated inventory is broad, but content entries, generators, link checker implementation, site code, branch protections and actual deployed assets were not read. This is a partial static review, not a catalog-wide editorial or security audit.

## Findings ledger

**AA-01 — Medium, confirmed static, high confidence: conflicting public counts.** [README:88-126](https://github.com/knarayanareddy/AI-Arsenal/blob/8ec0eef7698bccd93bddf089d0b49de67c858a93/README.md#L88-L126) labels an older 1,061-entry table “Current generated stats” immediately before an autogenerated 1,300-entry table. Readers cannot tell which source is current, and automated consumers may extract the wrong number. Remove the duplicate and derive the displayed counts from one traceable generated source; verify actual current totals rather than assuming either table is accurate.

**AA-02 — Medium, confirmed static, high confidence: UI status contradicts repository structure.** [README:146-149](https://github.com/knarayanareddy/AI-Arsenal/blob/8ec0eef7698bccd93bddf089d0b49de67c858a93/README.md#L146-L149) says the web UI belongs to a separate future repository, whereas the pinned `web/package.json` and Pages workflow define a present frontend build and deployment. This does not establish that the deployed site works. Document whether `web/` is a prototype, published UI or migration artifact, and identify its source data and owner.

**AA-03 — Medium, historical CI, high confidence in reported result only.** [Data Release Refresh](https://github.com/knarayanareddy/AI-Arsenal/actions/runs/41623668059) and [Weekly Refresh](https://github.com/knarayanareddy/AI-Arsenal/actions/runs/41508887156) failed at the pinned SHA. Their logs and causes were not sampled; no package vulnerability or stale deployed state is proven. Inspect step-level failures, identify the last published source SHA and recover only after verification.

**AA-04 — Medium, confirmed static, high confidence: no-skip check can suppress a failed Git range lookup.** [no-skip-ci:30-51](https://github.com/knarayanareddy/AI-Arsenal/blob/8ec0eef7698bccd93bddf089d0b49de67c858a93/.github/workflows/no-skip-ci.yml#L30-L51) pipes `git log` into a search with stderr discarded and `|| true`; an invalid or unavailable range can therefore look like “No [skip ci] markers.” The checkout fetches only 50 commits at [line 28](https://github.com/knarayanareddy/AI-Arsenal/blob/8ec0eef7698bccd93bddf089d0b49de67c858a93/.github/workflows/no-skip-ci.yml#L25-L29). Whether the platform triggers this workflow for a skipped commit or branch protection catches missing checks is unknown. Fail closed on range-resolution failure and separately require the validation check in branch protection.

**AA-05 — Medium, unverified risk, high confidence in workflow configuration.** [data-refresh:44-52](https://github.com/knarayanareddy/AI-Arsenal/blob/8ec0eef7698bccd93bddf089d0b49de67c858a93/.github/workflows/data-refresh.yml#L44-L52) publishes an orphaned generated branch, while [Pages:41-54](https://github.com/knarayanareddy/AI-Arsenal/blob/8ec0eef7698bccd93bddf089d0b49de67c858a93/.github/workflows/deploy-pages.yml#L41-L54) force-pushes the site branch. Those choices are not inherently erroneous, but rollback, artifact provenance and concurrent promotion are unverified. Preserve immutable release artifacts and demonstrate that a previously known-good data/site pair can be restored.

## Five-discipline assessment

Short supporting excerpts from the pinned ledger sources: AA-01, “Current generated stats”; AA-02, “future”; AA-03, both recorded refresh runs have `conclusion: failure`; AA-04, `2>/dev/null` and `|| true`; AA-05, `force_orphan: true` and `git push --force origin gh-pages`. AA-03 describes run metadata only; AA-05 is a provenance/recovery risk, not proof of an unsuccessful publication.

**Code/content correctness.** The collection uses schema-backed frontmatter but schema validity cannot establish factual accuracy, freshness or source authenticity. AA-01 and AA-02 are directly observable documentation drift; individual entries and generator consistency were not checked.

**Automation.** [PR workflow:36-41,61-66,86-110](https://github.com/knarayanareddy/AI-Arsenal/blob/8ec0eef7698bccd93bddf089d0b49de67c858a93/.github/workflows/on-pr.yml#L36-L110) declares changed-file checks, full editorial validation, global invariants and tests. A successful [CodeQL run](https://github.com/knarayanareddy/AI-Arsenal/actions/runs/41536873849) is historical and does not mean the application is secure. Link checking explicitly caps and samples URLs and treats transient results as warnings ([on-pr:155-178](https://github.com/knarayanareddy/AI-Arsenal/blob/8ec0eef7698bccd93bddf089d0b49de67c858a93/.github/workflows/on-pr.yml#L155-L178)); a green job does not establish all links were checked.

**DevOps.** Data and site publishing are separate workflows with different triggers. Source/version provenance, rollback, artifact retention and actual Pages configuration are unobserved. Pages uses mutable action tags where the CodeQL workflow uses SHA pins; this is a supply-chain improvement opportunity, not evidence of compromise.

**OWASP/security.** This static collection does not establish application authentication or private-user data handling. Write tokens are available to publication workflows, so branch permissions and trust boundaries need review. The link-check step describes SSRF defenses, but DNS rebinding and redirect handling were not inspected; HTML sanitization, injection into generated data and dependency integrity are unknown. Do not ingest repository content as trusted agent instructions merely because schema validation passes.

**UI/UX/accessibility.** A web package is present, but its components and rendered behavior were not inspected. Keyboard navigation, search announcements, responsiveness and reduced motion remain unknown; the README mismatch itself impedes discovery and maintenance.
