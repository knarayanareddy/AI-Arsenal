## Overview

Agent Rules Books publishes the same instruction set in three sizes, each a directory holding one Markdown file: a mini tier the README calls the recommended default for most coding agents, a nano tier for very tight context budgets, and a full canonical reference. The release matrix states the dimensions that matter for routing a model: the character count of each tier, the token cost at a given model, and the number of rules dropped as the size decreases. A coding agent loads one tier as a system prompt, so the choice is a trade between instruction coverage and the context window available for the task itself.

## Why it's in the Arsenal

The decision this catalog answers is how much instruction to keep permanently resident in an agent's context. Hand-rolling that guidance usually produces either a two-line README that a model ignores when code gets hairy or a 15 KB wall of prose that crowds out the task. Publishing the same advice at three measured sizes lets you pick the tier your context window and your risk tolerance actually support, and the line and rule counts let you compute that cost before you install.

## Architecture

There is no runtime here - the deliverable is Markdown, which is why the primary language field is empty. Each book directory is self-contained and namespaced, so installing one skill does not drag in the others, and the release matrix is generated by a deterministic counting convention over wc -l, list-item counts, and wc -c rather than by hand. Installation goes through the open Agent Skills CLI, with docs/USAGE.md covering always-on versus on-demand placement and docs/COMPATIBILITY.md mapping each rule set back to its source book.

## Ecosystem Position

The tiered-rule approach competes with the hand-written CLAUDE.md, AGENTS.md, and .cursorrules files teams already maintain, and it overlaps with other open rule packs rather than with any execution engine. Compared with a linter configuration such as an ESLint or Ruff setup, nothing here is machine-checked - these rules live entirely in the prompt. It complements the agent-skill collections in the sibling framework entries by supplying book-derived craft rules where those supply operational checklists, and it is an alternative to paying a consultancy to write the same house style guide for agent consumption.

## Getting Started

The Agent Skills CLI installs the whole library or a single rule set. Node.js with npm is the only prerequisite.

```bash
npx skills add ciembor/agent-rules-books --list
npx skills add ciembor/agent-rules-books --skill refactoring
npx skills add ciembor/agent-rules-books --all
```

For per-editor placement and scoped rules, read docs/USAGE.md in the repository, which covers Codex, Claude Code, and Cursor separately.

## Key Use Cases

1. Drop a nano tier into a system prompt that has no room for style guidance but still needs a floor on naming and function length.
2. Install one book at a time per repository so a Java service gets Clean Architecture rules without a React project inheriting them.
3. Use the full tier as a reference document the agent pulls on demand when a refactor touches boundaries it would otherwise rewrite carelessly.

## Strengths

- Three published sizes per book, so you can compute prompt budget before installing rather than after.
- Per-book directories mean selective installation; you pay for only the doctrine your stack needs.
- The release matrix publishes lines, rule counts, and byte sizes, so regressions in verbosity are visible between releases.
- Installable through the open Agent Skills CLI, which keeps the files portable across Codex, Cursor, and Claude Code.

## Limitations

These are advisory prompts, not enforcement. A model may ignore a rule it does not agree with, and a code review that catches the violation still happens on a human, so compliance is statistical rather than guaranteed. The prose is language-agnostic, which means it will not know about your ORM, your DI container, or your framework's own layering conventions. Because the material is distilled from copyrighted books, treat the repository as a summary and keep the original titles on hand wherever the underlying argument actually matters. Finally, rule volume competes for context with the task itself, so installing everything at the full tier will usually hurt more than help.
