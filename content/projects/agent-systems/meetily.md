## Overview

Meetily is a Tauri desktop application with a Rust backend and a Next.js frontend that records system and microphone audio simultaneously with ducking and clipping prevention. Transcription runs locally through either NVIDIA Parakeet (using the community ONNX conversion) or Whisper, with Vulkan-enabled Whisper builds on Windows, Metal and CoreML on macOS, and CUDA available through a configured source build on Linux. Summaries come from a selectable provider: Ollama locally, or Claude, Groq, OpenRouter, OpenAI or any custom OpenAI-compatible endpoint. It adds an import-and-enhance path to re-transcribe recorded audio with a different model or language, plus an editor view for summary generation. Roughly 31k stars and an MIT community edition sit alongside paid PRO and Enterprise tiers.

## Why it's in the Arsenal

The recurring problem is that meeting intelligence has a compliance tail. Recording a conversation is one decision; transcribing it on someone's server is another, and the second one is hard to walk back. Meetily's design removes the second decision entirely by keeping the audio path, the model and the storage local, and by letting the summary step be local too. The cost is desktop-shaped: it is an app per machine, not a service, so team deployment is a separate conversation.

## Architecture

Audio capture mixes microphone and system streams with intelligent ducking before writing to local storage. The Rust backend then dispatches the audio to a local ASR runtime: Parakeet via ONNX, or whisper.cpp-derived Whisper with platform-specific acceleration (Vulkan on the Windows installer, Metal/CoreML on macOS). Transcripts are persisted locally and fed to the chosen summary provider, which can be an Ollama model or any OpenAI-compatible endpoint. The Tauri shell wraps the Rust core with a Next.js UI, and the frontend provides the transcript view, editor and export surfaces. The project acknowledges code borrowed from whisper.cpp, Screenpipe and transcribe-rs.

## Ecosystem Position

Meetily competes with Otter, Fireflies and Granola in the meeting-notes category but on a completely different deployment model: local-only versus cloud SaaS, with no per-minute billing and no vendor holding the audio. It overlaps with content/projects/inference-engines entries such as faster-whisper and sherpa-onnx at the ASR layer while owning the capture, diarization-adjacent presentation and summary flow that those libraries deliberately do not. Compared with content/projects/agent-systems entries such as Whisper-based tooling, it is an end-user application rather than a library, and it points at Ollama in the inference-engines phase for the summarisation side rather than embedding a model server.

## Getting Started

Download the platform installer from Releases; Linux users build from source. Source builds need Rust and Node.js:

```bash
git clone https://github.com/Zackriya-Solutions/meeting-minutes
cd meeting-minutes/frontend
pnpm install --frozen-lockfile
./build-gpu.sh
```

On first run, choose Ollama for fully local summaries or point the app at an OpenAI-compatible endpoint.

## Key Use Cases

1. Confidential client meetings: capture, transcribe and summarise a privileged conversation entirely on your own hardware with no third-party processing.
2. Live captioning during calls: run Parakeet or Whisper on-device for real-time transcription where latency and offline operation both matter.
3. Re-transcribing archived audio: import an existing recording and re-run it through a different model or language via the import-and-enhance path.

## Strengths

- Genuinely local audio path: recording, transcription and storage never touch a cloud service, which is the compliance argument.
- Model choice at the transcription layer: Parakeet and Whisper are both supported, so speed and accuracy trade-offs are yours to set.
- Platform acceleration is real rather than aspirational (Vulkan on Windows installers, Metal/CoreML on macOS), so it runs at usable speeds on commodity hardware.
 - Import-and-enhance lets you reprocess old recordings without re-recording or losing the original.

## Limitations

The free community edition does not include speaker diarization, which is the feature many buyers actually want and which the README positions as a PRO item. Team and enterprise deployment is a paid conversation, so the OSS edition is fundamentally single-machine. Linux has no packaged installer and needs a source build with the correct acceleration flags; Windows ships a Vulkan Whisper build that requires an AVX2-capable CPU. PRO is built on a different codebase, so migration expectations between editions should be set carefully. With roughly 350 open issues and heavy release activity, expect rough edges in the desktop app rather than in the model layer.
